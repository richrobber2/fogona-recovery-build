- Dedicated recovery_a/b, header4, ramdisk only; use matching boot kernel.
- Recovery100MiB, boot/vendor_boot96MiB, init_boot8MiB.
- Super6710886400 bytes, mot_dp_group active maximum6706692096 bytes.
- f2fs userdata with fscrypt v2, inlinecrypt_optimized, wrappedkey_v0,
  metadata encryption and /metadata/vold/metadata_encryption key directory.
- Slot-aware raw image paths; no stale unsuffixed /boot assumptions.
- Vendor level2026-08-01, no2099 future-date or AVB disable flags.
- No empty kernel input; verified private prebuilt/boot.img is used instead.
- Embedded /system/bin/device-rescue.sh. It is invoked explicitly from the
  touch recovery's Advanced/Terminal, never automatically at boot.

Build prerequisite:
prebuilt/boot.img is ignored in the original tree and excluded from source ZIPs.
The public build repository includes its compressed, verified stock boot input
with explicit user permission; no userdata or patched init_boot image is included.
It must exactly match boot_a from ../backups/manifest.json in this workspace.
Run python3 ../validate-port.py from the original local tree (or use its
absolute path). It evaluates BoardConfig using GNU make and checks image
headers, capacities, encryption flags, payload identity and git diff syntax.

The full Android/TWRP source tree and its Linux host prebuilts are not installed.
This workspace has about11GiB free on an ARM64 Android host. A full recovery build
needs a suitable Linux build environment and substantially more source/output
space. GitHub Actions builds now run in the public build repository. Earlier attempts
failed source/configuration validation before producing an image. A source ZIP
is not bootable. See the workflow run and local PORT-PROGRESS.txt for current

closure check. Upstream deferred handling permits unused, omitted test packages;
missing dependencies reachable from recoveryimage and its linker remain fatal.
The staged ramdisk audit is an additional mandatory gate.

  no legacy fb0 was observed. Actual TWRP rendering/backlight/touch not tested.
- Matching vendor_boot holds first-stage/storage/DRM modules. SPI binding on
  this phone verifies nova_0flash_mmi as its active touch driver; modules.dep
  identifies dependencies, and /vendor/firmware contains djn Novatek firmware.
  The EROFS vendor/vendor_dlkm/system_dlkm mounts, loader request and firmware
  fallback symlink are configured. Actual recovery loading/touch remains untested.
- Crypto build switches do not prove hardware-backed wrapped-key decryption.
  Without data access, module-disable actions deliberately refuse to proceed.
- AVB signing/rollback acceptance and Motorola slot/recovery loading must be
  established before producing any deployable image.
- Phone-only rollback remains unresolved. Do not change slot or flash either
  recovery while the phone is the sole working control device.

Prior normal-boot stalls remain unexplained. All existing device modules remain
